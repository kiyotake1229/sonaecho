## 概要

そなえ帳は、家庭の備蓄と防災をまとめる手帳アプリ（清武の自主企画）。世帯人数から水・食料・トイレなどの必要量を計算し、期限を見守り、非常時は通信なしで使える道具（ライト・ホイッスル・家族カードなど）になる。Web版（PWA）は GitHub Pages で公開済みで、iOS版は Capacitor のプロジェクトを作り GitHub Actions で署名なしビルドの成功まで確認済み。実機確認・スクリーンショット・申請が残っている。コミット 9587a12 時点の内容。以後の変更は #0002 以降の文書に記録する。

## 仕様

### 画面と機能

下部のタブは5つ（`nav#tabs` の `data-tab`: `home` / `stock` / `check` / `sos` / `set`）。各画面は `section#s-<タブ名>` に JS で描画する。細かい入力は下から出るパネル（`#sheet`、関数 `openSheet`）で行う。

**初回起動（オンボーディング）**

- `S.setup.done` が false のとき `#ob` に3ステップを表示する（`startOnboarding` / `renderOb`）
- 1: アプリの紹介。2: 世帯人数（大人・子ども・乳幼児・高齢者・ペット、各0〜20）と目標日数（3日分／1週間分）
- 3: 家にある物の数を入力する。対象は `OB_PICKS` の12品。乳幼児がいれば「おむつ」、ペットがいれば「ペットフード」が加わる
- 「はじめる」で入力した品を備蓄に登録する（期限は空）。「あとで登録する」で飛ばせる（`finishOb`）
- 終了時、iOS版は通知の許可を1回だけ求める（`askNotif`、`settings.notifAsked`）

**ホーム（`renderHome`）**

- そなえ度（0〜100）をリングと段階名で表示。タップで内訳を開く（`sheetScore`）
- 必要量に対するバー（`barRow`）: 飲料水・主食主菜・簡易トイレ・カセットボンベ。世帯によりおむつ・ペットフードが加わる
- バーの色: 充足率100%以上=緑、50%以上=通常色、25%以上=黄、25%未満=赤
- 見出しの文: 足りない分類のうち、重みを加味した上位2つの名前を出す
- お知らせ: 期限切れ／`notifyDays` 日以内に期限／買い足しリストの未購入／点検日まで14日以内／備蓄0件のときの登録案内
- もしもの道具のショートカット4つ（ライト・ホイッスル・家族カード・安否連絡）
- 日替わりのひとこと（`TIPS` 21件を日付で順番に表示）
- 次の点検日（3月1日・9月1日）と「点検した」ボタン（`doCheckDone` が `settings.lastCheck` に今日を記録）
- ヘッダーにライト/ダークの切替ボタン（ホームのみ）

**そなえ度の算出（関数 `score`）**

| 項目 | 配点 | 点の入り方 |
|------|------|-----------|
| 飲料水 | 30 | 充足率に比例 |
| 主食・主菜 | 25 | 充足率に比例 |
| 簡易トイレ | 15 | 充足率に比例 |
| カセットボンベ | 5 | 充足率に比例 |
| おむつ | 8 | 乳幼児がいるときだけ。充足率に比例 |
| ペットフード | 6 | ペットがいるときだけ。充足率に比例 |
| 明かり・電源 | 5 | 期限切れでない「明かり・電源」の品が1件以上で満点 |
| 救急・薬 | 5 | 同じく「救急・薬」の品が1件以上で満点 |
| 高齢者・介護 | 4 | 高齢者がいるときだけ。「高齢者・介護」の品が1件以上で満点 |
| 非常持ち出し袋 | 10 | チェックリスト「非常持ち出し袋」の達成率に比例 |
| 連絡の備え | 5 | 家族カード（名前か電話が1件）で半分、集合場所①か避難所の入力で半分 |
| 期限管理 | 5 | 期限切れ0件で満点、1〜2件で半分、3件以上で0 |

- そなえ度 = 得点の合計 ÷ 配点の合計 × 100（四捨五入）。配点の合計は世帯構成で変わる
- 段階名（`LEVELS`）: 0 これから / 20 はじめの一歩 / 40 そなえ中 / 60 しっかり / 80 安心 / 100 万全
- 充足率（`cov`）= 備えている量 ÷ 必要量（上限1）

**必要量の計算（`CATS` の各分類の `need`）**

- 人数 p = 大人＋子ども＋乳幼児＋高齢者（関数 `HH`）。ペットは含まない。d = 目標日数（3 または 7）
- 子ども・乳幼児・高齢者も大人と同じ量で計算する

| 対象（分類 id） | 計算式 | 単位 | アプリ内の根拠表示 |
|-----------|--------|------|------------------|
| 飲料水（`water`） | 3 × p × d | L | 1人1日 3L |
| 主食・主菜（`food`） | 3 × p × d | 食 | 1人1日 3食 |
| 簡易トイレ（`toilet`） | 5 × p × d | 回 | 1人1日 5回 |
| カセットボンベ（`cook`） | 0.5 × p × d を切り上げ | 本 | 1人1日 0.5本 |
| おむつ（`baby`） | 8 × 乳幼児数 × d | 枚 | 1人1日 8枚（乳幼児がいるとき） |
| ペットフード（`pet`） | ペット数 × d | 日分 | 1匹1日 1日分（ペットがいるとき） |

- 備えている量（`have`）= 同じ分類の品の「数量 × 1つあたりの量（`per`）」の合計。期限切れの品は数えない（`isExpired`）
- `per` が0の品は量に数えない。プリセットで `per` が0より大きいのは16品（例: 水 2L=2、水 500ml=0.5、アルファ米=1、乾パン・ビスケット=3、簡易トイレ=1、カセットボンベ=1）
- 根拠の出典は、README とアプリ内表示では内閣府「災害に対するご家庭での備え」・農林水産省「家庭備蓄ポータル」。数値と出典の照合は本書では未確認

**備蓄タブ（`renderStock`）**

- 3つの表示を切り替える（変数 `stockSeg`: `list`=一覧 / `exp`=期限順 / `shop`=買い足し）
- 一覧（`stockList`）: 分類チップで絞り込み。必要量のある分類を選ぶと、その分類のバーを上に出す。並びは分類順→期限の早い順
- 一覧の±ボタンで数量を変える（`chgQty`。0未満にはならない）
- 期限順（`stockExp`）: 期限切れ／`notifyDays` 日以内／90日以内／それ以降／期限なし の5グループ
- 品の詳細（`sheetItem`）: 「1つ使った」（`consume`）・編集・削除（確認あり、`delItem`）
- 追加（右下の＋ `#fab` → `sheetAdd`）: プリセットから選ぶ（`renderPresets` / `pickPreset`）か、自分で入力（`sheetForm`）
- プリセットは `PRESETS` の94件。名前の部分一致と分類で絞れる。同名の品が登録済みなら「登録済み・追加」と出る
- プリセットを選ぶと、単位・1つあたりの量・置き場所と、期限＝今日＋目安の保存期間（月）が入る。期限は目安なので実物の日付に直す前提
- 入力項目: 名前・分類・単位・数量・1つあたりの量（必要量のある分類だけ）・期限・置き場所（`PLACES` 11か所）・メモ（`saveForm`）
- 分類の選択肢とプリセットには、世帯に該当しない分類（乳幼児・高齢者・ペット）を出さない（`activeCats`）
- 期限の表示（`expState`）: 期限切れと当日=赤、`notifyDays` 日以内=黄、それ以外=通常。期限切れか間近があると「備蓄」タブに赤い点が付く

**期限管理と買い足しリスト（ローリングストック）**

- 「1つ使った」: 数量を1減らし、`stats.consumed` を1増やし、買い足しリスト（`S.shop`）に入れる。未購入の同じ品があれば個数を1増やす
- 買い足しリスト（`stockShop`）: 自由入力で追加（`addShopFromInput`）、チェックで「買った」（`toggleShop`）、削除、「まとめて消す」
- 備蓄と紐づく行（`itemId` あり）には「備蓄へ」ボタン（`shopToStock`）。押すと編集画面が開き、買った個数が数量に足される。保存で確定
- 期限の通知はiOS版だけ（「PWA・iOS」参照）。Web版はホームのお知らせだけ

**チェックタブ（`renderCheck`）**

- 4つのリスト（`CHECKLISTS`）: 非常持ち出し袋（`bag`）・在宅避難の備え（`home`）・家の安全対策（`safety`）・情報・連絡の備え（`info`）
- 項目数: 基本は20・15・13・11の計59項目。条件つき項目は「非常持ち出し袋」だけにあり、乳幼児4・高齢者3・ペット3（全部該当で計69項目）
- リストを開き、タップでチェック（`sheetChecklist` / `toggleCheck`）。自分の項目を追加・削除できる（`addCustom` / `delCustom`）
- 画面上部に全体の進み具合、各リストに達成率を表示

**もしもタブ（`renderSos`）＝通信なしで動く道具箱**

- ライト（`openLight`）: 画面全体を白くする。対応ブラウザでは自動消灯を止める（`navigator.wakeLock`）。SOS のモールス点滅（`startSos`: 短220ms・長660ms）
- ホイッスル（`toggleWhistle` / `stopWhistle`）: Web Audio で合成（矩形波2800Hz＋のこぎり波3520Hz、450msごとに音程を切り替え）。音源ファイルなし
- 家族カード（`sheetFamily` / `sheetFamilyForm` / `saveFamily`）: 名前・続柄・血液型・電話・アレルギー・持病/常用薬・メモ。電話番号があれば発信ボタン（`tel:`）
- 家族カードはテキストで共有できる（`shareFamily` / `familyText`。集合場所・避難所も含む）
- 集合場所・避難所（`sheetMeet`）: 集合場所①（近く）・②（遠く）・避難所・メモ
- 安否連絡（`sheetMsg`）: 名前・今いる場所・時刻・連絡先・ひとことで定型文を作る。「コピー」か「送る」（`shareText`）。名前・場所・連絡先は保存し、ひとことは保存しない
- 災害メモ（`sheetNotes` / `addNote`）: 時刻つきで記録。表示は新しい50件。共有と全消去
- 行動ガイド（`GUIDES`）: 地震・津波・台風大雨・火災・停電・断水。開閉式
- 災害用伝言ダイヤル171の手順と発信ボタン（`tel:171`）
- 電池と水を長持ちさせるコツ（`SAVE_TIPS` 6件）
- 画面の下に「実際の避難は公的機関の情報を優先」の注意書き

**設定タブ（`renderSet`）**

- 世帯: 大人・子ども・乳幼児・高齢者・ペット（各0〜20）。人数の合計が0になると大人を1に戻す（`chgHH`）。目標日数は3日分／1週間分
- 通知: 期限の通知 ON/OFF（`notifyExp`）、何日前か（14/30/60/90日、`notifyDays`。期限の色分けにも使う）、点検日のリマインド（`notifyCheck`）、「通知をテスト」（iOS版だけ表示）
- 表示: テーマ（端末に合わせる／ライト／ダーク）
- データ: バックアップと復元、サンプルデータの読み込み、すべて削除（2回確認）
- このアプリについて: バージョン（`APP_VER` = 1.0.0）、出典、登録数と使用回数（`stats`）

### データの保存

- 保存先はブラウザの `localStorage`。キーは `sonaecho-v1`（定数 `STORE_KEY`）。全データを1つの JSON で保存する（関数 `save`）
- iOS版は同じキーで Capacitor Preferences にも保存する（0.3秒遅らせて書く）。起動時に localStorage が空で Preferences にデータがあれば戻す（`restoreFromNative`）
- 外部への送信はしない

データの形（`DEF` の初期値。実行中は変数 `S`）:

| キー | 内容 |
|------|------|
| `v` | 形式の版（1） |
| `setup.done` | 初回設定が済んだか |
| `hh` | 世帯。`adults` `kids` `infants` `elderly` `pets` と目標日数 `days`（3/7） |
| `items[]` | 備蓄。`id` `added` `name` `cat` `qty` `unit` `per` `exp`（YYYY-MM-DD か空） `place` `memo` |
| `shop[]` | 買い足し。`id` `name` `qty` `unit` `itemId`（備蓄と紐づくとき） `done` |
| `checks` | リストIDごとのチェック。例 `{"bag":{"笛（ホイッスル）":true}}`。キーは項目の文言そのもの |
| `custom` | リストIDごとの自分の項目。`[{key:"c_…", label}]` |
| `family[]` | 家族カード。`id` `name` `rel` `blood` `phone` `allergy` `meds` `memo` |
| `meet` | 集合場所。`p1` `p2` `shelter` `memo` |
| `notes[]` | 災害メモ。`ts`（ミリ秒） `text` |
| `msg` | 安否連絡の入力。`name` `place` `phone` |
| `settings` | `theme`（auto/light/dark） `notifyDays` `notifyExp` `notifyCheck` `lastCheck` `notifAsked` |
| `stats` | `consumed`（使った回数） `added`（登録数） |

- 読み込み（`load`）は初期値と合成する。キーが欠けた古いデータでも動く
- バックアップ（`sheetBackup`）: `S` 全体を JSON 文字列にして、コピーか共有。ファイルの書き出し機能はない
- 復元（`restoreBackup`）: 文字列を貼り付ける。`v` が1で `items` が配列でなければ拒否する。確認のうえ全体を上書き
- すべて削除（`resetAll`）: localStorage と Preferences のキーを消し、オンボーディングに戻る
- サンプルデータ（`loadDemo`）: 大人2・子ども1・高齢者1・ペット1、3日分。備蓄27件（期限切れ・期限間近を含む）、買い足し3件、チェックの一部、家族カード4人、集合場所、安否連絡を入れる
- サンプルの期限は読み込んだ日からの相対日付。既存の備蓄があれば確認して上書きする。読み込んだ内容は保存される
- `?demo=1`: 初回設定前（`setup.done` が false）の端末だけ、オンボーディングの代わりにサンプルデータで起動する。設定済みの端末では読み込まない
- 撮影用の URL パラメータ（`init` 内。`tools/take-shots.sh` が使う）: `shot=1`（トーストとアニメーションを止める。定数 `SHOT`）、`theme=`、`tab=`、`seg=`、`open=`（family / msg / add / score / meet / notes / bag / item / light / guide）、`ob=1`

### 通信と外部リソース

- アプリ本体は外部と通信しない。`index.html` に `fetch`・`XMLHttpRequest`・`WebSocket` はない
- CDN・Google Fonts・外部画像の読み込みはない。フォントは端末標準（`-apple-system`、`"Hiragino Sans"` など）
- アイコンは HTML 内の SVG（`<symbol id="i-…">`）。音は Web Audio で合成
- 読み込むのは同じフォルダのファイルだけ: `manifest.json`・`apple-touch-icon.png`・`icon.svg`・`sw.js`
- `sw.js` は同じサイト内のファイルをキャッシュ用に取得する（外部ではない）
- 端末の機能を使う箇所: `tel:` リンク（発信）、`navigator.share`（共有）、`navigator.clipboard`（コピー）、`navigator.wakeLock`（消灯防止）、`navigator.vibrate`（振動）
- `tools/` のスクリプトは開発者の Mac で Chrome と Python（PIL）を使う。アプリの動作とは関係ない

### 技術構成とコードの地図

- 素の HTML / CSS / JavaScript。フレームワーク・ビルド工程・外部ライブラリなし
- `index.html` の並び: `<style>`（CSS 変数でライト/ダーク。`:root[data-theme="dark"]`）→ `<body>` の SVG アイコン定義と画面の枠 → 1つ目の `<script>`（データ）→ 2つ目の `<script>`（処理）
- 描画は各 `render…` 関数が `innerHTML` を作り直す方式。ボタンは `onclick` 属性で関数を呼ぶ
- 画面の状態（`tab` `stockSeg` `stockCat`）は保存しない
- 分類ごとの色はクラス `cat-c1`〜`cat-c10`（`CATS` の `c`）

1. 1つ目の `<script>` 冒頭の `STORE_KEY` と `CATS`（分類と必要量の式）

3. `have` / `cov` / `score`（計算）
4. `render` / `showTab`（画面の切り替え）
5. 末尾の `init`（起動処理・URL パラメータ・Service Worker 登録）

### 既知の制限・注意点

**README・資料と実装の食い違い（実装を正とする）**

- プリセット数: README・`岩崎さんへの提案書.md`・`プレゼンの進め方.md`・`提案資料/提案書.html`（「120+」）・引き渡し手順の App Store 説明文の下書きは「120種類以上」。実装の `PRESETS` は94件。申請前にどちらかを合わせる必要がある
- チェックリストの項目数: README と提案書は「計60項目超」。実装は基本59項目、条件つきを全部足して69項目
- 条件つき項目の範囲: README は4リストで項目が増えるように読める。実装で増えるのは「非常持ち出し袋」だけ
- そなえ度に入るチェックリスト: README は「チェックリスト」から算出と書く。実装で点数に入るのは「非常持ち出し袋」だけ
- 必要量の根拠表: README の表にペットフード（1匹1日1日分）がない。実装にはある
- 期限順の区切り: README は「30日以内」。実装は設定の `notifyDays`（14/30/60/90日）に連動する（初期値30）
- 共有シート: README と引き渡し手順はネイティブ機能に「共有シート」を挙げる。実装は `@capacitor/share` を入れているが呼んでおらず、`navigator.share` に頼っている。iOS アプリ内で共有シートが開くかは未確認（開かなければコピーになる）。`@capacitor/app` も入っているが `index.html` から呼んでいない
- 本体サイズ: README は約125KB。実際は122,972バイト

**動作・コード上の注意（コードからの読み取り。実機での再現は未確認）**

- `ios-app/www/` と `ios-app/ios/App/App/public/` の `index.html` は初回コミット時点の古いコピー（撮影用パラメータなし）。手元でビルドする前に `npm run sync` が必要。GitHub Actions は毎回作り直す
- チェックの保存キーは項目の文言。`CHECKLISTS` の文言を変えると、保存済みのチェックが外れる
- `loadDemo` と `OB_PICKS` はプリセットを名前で探す。`PRESETS` の名前を変えるとサンプルデータやオンボーディングがエラーになる
- 世帯に該当しなくなった分類の品（例: ペットを0にした後のペットフード）を編集すると、分類の選択肢にないため先頭の「水」に変わって保存される（`sheetForm` の選択肢が `activeCats` だけのため）
- 点検日: `nextCheckDate` は今日より後の日付だけを返す。そのためホームの「今日は備蓄の点検日」の表示は出ない。点検日当日の10時より前にアプリを開くと、その日の通知は次回分に置き換わる
- 備蓄の削除（`delItem`）・復元・サンプル読み込みでは通知を作り直さない。次の起動や保存まで古い予約が残る
- Web版で「期限が近づいたら知らせる」を OFF にしても、ホームのお知らせは消えない（`notifyExp` は通知の予約にだけ使う）
- データが空でも「期限管理」が満点になるため、そなえ度は0ではなく5前後から始まる
- 撮影用の `theme=` は設定値を書き換える。その後に保存が走るとそのまま残る
- 本番URLに `?demo=1` を付けて開くと、その端末のブラウザにサンプルデータが保存される

**環境による差**

- 通知・Preferences への保存・ネイティブの触覚は iOS 版だけ

- ホイッスルがマナーモードでも鳴る（`ios-app/README.md` の記載）、音量、実機での触覚・通知は未確認（README の残作業）
