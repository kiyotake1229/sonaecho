# iOSの共有シート・点検日などの不具合修正（そなえ帳）

- 管理番号: #0006
- 種類: BUG（バグ修正）
- 対象: アプリ本体（APP）
- 作成日: 2026-09-23
- 関連: #0001（既知の制限・注意点で見つかっていたもの）

## 概要

#0001 の「既知の制限・注意点」に挙がっていた不具合と、今回の確認で見つかった表示の崩れを直した。とくに、iOS版の「共有」がネイティブの共有シートを呼んでいなかった点は、App Store 申請の説明（ネイティブ機能に共有シートを挙げている）と食い違っていたため優先して直した。

## 対象ファイル

- `index.html` … `shareText`、`sheetForm`（分類の選択肢）、`checkDates`・`nextCheckDate`・`dueCheckDate`・`renderHome`（点検の案内）・`finishOb`、`scheduleNotifications`・`queueNotify`・`save`、`init`・`applyTheme`（`themeOverride`）、`render`（備蓄タブの点）、CSS `.toast`・`.btn.sm`

## 変更内容

| 不具合 | 直し方 |
|------|------|
| iOS版の共有が `navigator.share` だけで、入れてある `@capacitor/share` を呼んでいなかった（WebView では共有シートが開かず、コピーになるおそれ） | iOS版は `CAP.Share.share` で共有シートを開く。取り消しはエラー扱いにしない。ブラウザ版は従来どおり Web Share API、なければコピー |
| 世帯から外れた分類の品（ペットを0にした後のペットフードなど）を編集すると、分類が「水」になって保存された | 分類の選択肢に、その品の今の分類を足す |
| 点検日: 今日より後の日付しか見ておらず、「今日は点検日」が出なかった。点検日の朝10時前に開くと、その日の通知が次回分に置き換わった | 3月1日・9月1日を過ぎていて、その30日前以降に「点検した」がなければ「点検の時期です（9月1日〜）」を出す。通知は、まだ10時が来ていない一番近い点検日に予約する。初回設定を終えた日を最初の点検とみなす |
| 削除・復元・サンプル読み込みで通知を作り直していなかった | 保存のたびに1.2秒後にまとめて作り直す（`queueNotify`）。期限の通知は、残りのある品を期限の近い順に最大40件 |
| 撮影用の `?theme=` が設定に保存された | 表示だけ切り替え、設定には書かない（`themeOverride`） |
| Web版で「期限が近づいたら知らせる」をオフにしても、ホームのお知らせが消えなかった | オフのときは期限間近のお知らせと備蓄タブの点を出さない（期限切れは出す） |
| 通知（トースト）が画面の半分の幅で折り返し、「元に戻す」を付けると縦に潰れた | 文字の長さに合わせて画面幅の92%まで広げる |
| 小さいボタン（ホームの「点検した」など）の文字が2行に折れた | 折り返さない |

## 確認URL

| 環境 | URL |
|------|-----|
| ローカル | http://localhost:8765/ |
| 開発確認（Artifact） | https://claude.ai/artifact/1pFsgnpLpnANoWnvf9qrzY |
| 本番（GitHub Pages） | https://kiyotake1229.github.io/sonaecho/ |

確認した内容:

- Capacitor の偽物を入れたコピー: 共有で `Share.share`（text・title）が呼ばれること。起動時と保存後に通知が作り直され、期限13件と点検日（ID 4001）が予約されること
- ブラウザ: ペットを0にしてペットフードを保存しても分類が pet のままのこと。点検の判定（前回 9/23 → 案内なし、8/10 → なし、7/20 → 9/1 から「点検の時期です」）。`?theme=dark` で開いても保存値が auto のままのこと。トーストとボタンの表示
