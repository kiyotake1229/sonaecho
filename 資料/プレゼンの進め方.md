## 1. 1分版（エレベーターピッチ）

> 今回は、お題をもらってではなく、**テーマ選びから自分で決めて**1本作りました。
> 家庭の備蓄と防災の手帳アプリ「そなえ帳」です。
>
> 国は「最低3日、できれば1週間分」の備蓄を呼びかけていますが、実際には**「何をどれだけ」がわからない**のが一番の壁です。
> このアプリは家族の人数を入れると、水・食料・トイレの必要量を計算して「あと水9L、トイレ30回」と具体的に出します。
> 期限が近いものは知らせて、「1つ使った」を押せば買い足しリストに入る。**期限切れを出さない**設計です。
>
> そして、もしもの時はライト・ホイッスル・家族カード・安否連絡の道具箱になる。**全部、通信なしで動きます。**
> うちがずっと守ってきた「通信なし・端末内保存」の方針が、防災ではそのまま売りになります。
>
> Web版は公開済み、iOSのプロジェクトも組んであって、申請文面まで下書き済みです。

### 2-1. 導入（1分）

話すこと：
- これまでの5本はお題をもらって作った。今回は「自分ならこれを出す」というテーマで作った
- 選んだ基準は3つ。**需要がある／年2回必ず話題になる／うちの作り方が強みになる**
- 結論から言うと、Web版は完成して公開済み。iOSも申請一歩手前まで来ている

### 2-2. 課題と着眼点（2分）

話すこと：
- 内閣府・農水省は「最低3日、推奨1週間」の家庭備蓄を呼びかけている。水は1人1日3L、トイレは1日5回。**でも1週間分を備えている家庭は少ない**
- 理由は「何をどれだけ買えばいいかわからない」「買っても期限切れにしてしまう」の2つ
- 既存アプリは、自治体アプリ＝情報配信が中心で家庭の備蓄は管理できない。備蓄管理アプリ＝数を数えるだけで、UIが古い・広告が多い・非常時に使う機能がない
- **3月11日と9月1日（防災の日）** に毎年メディアとストアで特集が組まれる。リリースと更新をここに合わせられる

ひとこと添えるなら：
> 「防災は、必要だとみんな分かっているのに動けない領域です。動けない理由を1つずつ消すアプリにしました」

### 2-3. デモ（4分）※台本

**① ホーム（30秒）**
> 「4人家族・3日分の設定です。そなえ度80、『安心』。バーを見ると、飲料水があと9L、簡易トイレがあと30回足りない。**何を買えばいいかが、この画面だけでわかります。**」
> （リングをタップ）「内訳です。何をすれば点数が上がるかも見えます」

**② 備蓄 → 期限順（1分）**
> 「期限が近い順に並びます。カップ麺が期限切れ、30日以内が4点」
> （カップ麺をタップ →「1個使った」）「使ったら押す。数が減って、**買い足しリストに自動で入ります**。買い物のときにこのリストを見て、買ったら『備蓄へ』で戻す。これで『食べて買い足す』ローリングストックが一周します」
> 「ちなみに期限切れは必要量に数えません。数字がごまかされない作りです」

**③ 備蓄 → ＋（30秒）**
> 「登録はプリセットから選ぶだけ。120種類以上。水2Lなら『1本＝2L』、期限の目安、置き場所まで入っています」

**④ チェック（30秒）**
> 「持ち出し袋・在宅避難・家の安全・連絡の備え、4つのリスト。**ペットや高齢者がいる家庭では項目が自動で増えます**」

**⑤ もしも（1分）**
> 「ここが他のアプリにない部分です。ライト（点けてSOS点滅を見せる）、ホイッスル（音量注意・一瞬だけ）、家族カード（血液型・アレルギー・持病・電話）、安否連絡（定型文を見せて『送る』で共有シートが開く）」
> 「家族カードや定型文は、**平時に入れておくから非常時に使える**。備蓄の手帳と道具箱を1つにした理由がこれです」

**⑥ 機内モード（30秒）※一番大事**
> 「最後に。（機内モードにする）このまま全部やり直しても、全部動きます。**通信を一切使っていないので、圏外でも停電でもサーバーが落ちても開ける。** これは防災アプリとしていちばん大事な性能だと思っています」

### 2-4. 何が違うのか（1分）

3つに絞って言う：
1. **必要量から逆算する**（数を数えるだけのアプリとの違い）
2. **期限切れを出さない設計**（使う→買い足す→戻すが一周する）
3. **平時と非常時をひとつのアプリで**、しかも通信なし

### 2-5. 展開と収益（1分）

- **v1.0**：無料・広告なし。防災の日／3.11に合わせて出し、レビューと利用状況を見る
- **v1.1**：買い切りの「プラス」（480円程度）。バーコード登録、家族間のQR共有（通信なしのまま）、複数の備蓄場所
- **法人向け**：企業・オフィスの備蓄管理モード。東京都は条例で事業者に3日分の備蓄を努力義務にしている。総務・防災担当が対象。自治体・保険会社・防災用品メーカーへのOEMも考えられる

ひとこと：
> 「まず無料で『防災』カテゴリでの評価を作って、法人向けを次の柱にする順番で考えています」

### 2-6. 現在の状態とお願い（1分）

- Web版：完成・公開済み（ https://kiyotake1229.github.io/sonaecho/ ）
- iOS：Capacitorで構築済み。手元にXcodeがないので GitHub のmacOS環境でビルドが通ることまで確認済み
- 申請文面（アプリ名・説明・キーワード・カテゴリ・プライバシー・審査用の英文備考）は下書き済み
- **お願いしたいこと**：
  1. Xcodeのある環境で `npx cap sync ios` → 実機で動作確認（触覚・通知・音量・共有）
  2. Apple Developer Program の手配
  3. 問題なければ「コツコツ」と同じ流れで申請

## 3. 想定質問と答え

| 質問 | 答え |
|---|---|
| 競合はいないの？ | 備蓄管理アプリ自体はある。ただ「必要量から逆算」「使う→買い足すの一周」「非常時の道具箱」を通信なしで揃えたものは見当たらない。自治体アプリは情報配信が中心で補完関係 |
| 必要量の根拠は？ | 内閣府「災害に対するご家庭での備え」と農水省「家庭備蓄ポータル」。水3L／食3食／トイレ5回、最低3日・推奨1週間。アプリ内にも出典を明記 |
| 行動ガイドの内容は大丈夫？責任は？ | 一般的な防災指針の範囲。医療・診断に当たる内容は入れていない。アプリ内に「実際の避難は公的機関の情報を優先」と明記。審査対策にもなる |
| 通知はWeb版でも届く？ | Web版はアプリを開いたときのお知らせのみ。iOS版はローカル通知で閉じていても届く（期限N日前、年2回の点検日） |
| データはどこに？ | 端末内のみ。通信ゼロ。家族カードのような個人情報こそ端末外に出さない設計。App Storeのプライバシーは「収集しません」 |
| 機種変更したら？ | 設定のバックアップで文字列をコピー／共有して復元。v1.1でQRコードによる家族間共有も予定 |
| 審査4.2（WebViewだけのアプリ）は？ | 完全オフライン・端末内保存・継続利用の設計に加え、ローカル通知・触覚・共有シートを実装。コツコツと同じ根拠で通せる |
| どれくらいで作った？ | 企画・設計・実装・文書まで1日。単一HTML約125KB、外部ライブラリなし |
| Android は？ | Web版（PWA）がそのまま動く。ストア配布が必要なら Capacitor で Android も生成できる |
| 法人向けは本当に需要ある？ | 東京都帰宅困難者対策条例で従業員3日分の備蓄が努力義務。総務担当は表計算で管理しているケースが多く、複数拠点・点検記録・期限一覧が欲しいという声が典型。まず個人版で実績を作ってから提案する |
| 収益化で広告は？ | 入れない方針。非常時に開くアプリに広告は合わないし、通信なしの方針とも矛盾する。買い切りと法人向けで回収 |

## 4. 話し方のコツ

- 最初の1分で「自分で選んだテーマ」「完成している」「通信なしが強み」の3点を言い切る
- デモは**スマホを持って操作しながら**話す。提案書ページは補助で、読み上げない
- 「1個使った → 買い足しリスト」と「機内モードで全部動く」の2か所は必ず見せる。時間がなければ他は削る
- 数字は3つまで（3L／3日→1週間／120種類）。多く言わない
- 最後は「お願いしたいこと」を1〜3で具体的に言って終わる
